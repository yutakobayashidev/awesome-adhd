# 1. 反省ログを、AIが起動時に自動で読み込む

## メリット：

同じミスを何度も繰り返してしまうこと

- 失敗の記録を、指示書の本体ではなく別ファイルに分ける
- そのファイルをAIの起動時フック（起動と同時に自動実行される設定）で毎回読み込ませる
- 読み込むのは直近5件だけに絞る。全件だと量が多くて実質読まれない
- 指示書の本文には「読み返しは自動実行が代行する」と書いて、役割を分ける

## 得られること：

反省ノートが機能しなかった原因は、書かないことではなく書いた後に開かないことでした。開く行為を消すと、反省が初めて積み上がります。3ヶ月で96件たまりましたが、価値は件数ではなく毎回強制的に目に入る点にあります。

## 導入のためのプロンプト：

```
失敗ログを毎回自動で読み込む設定を作ってください。

1. 私の失敗・学びを記録するファイルを作る
2. 見出し単位でエントリを区切り、末尾5件だけを抜き出すスクリプトを書く
3. そのスクリプトを、セッション開始時に自動実行される設定に登録する
4. 1エントリが長い場合は途中で切る（量が多いと実質読まれないため）

作った後、動作確認まで一緒にやってください。
```

# 2. 「雑に書くだけ」の入口を、別に用意する

- 日報などを「殴り書きで貯める」と「整えて提出する」の2段に割る。
- 前段は書式・順序・完成度を要求せず、1日1ファイルに追記するだけにする。
- 後段が前段の殴り書きを読んで提出形に展開する。
- 前段の指示書には「書式を整えない」と明記する。

着手できない原因を、やる気ではなく「最初の1手が定義されていない」「体裁負荷まで同時に背負っている」と捉え、整える負荷を後段へ逃がす。

---

# 3. サボる時の言い訳を、ルールに先に書いておく

- 「急ぎだから今回は飛ばす」「短いから確認は不要」など、自分が実際に使う言い回しを列挙する。
- それをルール本文に「〜と判断しがち」の形で書き込む。
- 過去の失敗記録を材料にすると、実際に使った言い訳が拾える。

「気をつける」対象を抽象ではなく具体的な言い訳の文言にすることで、その言葉が頭に浮かんだ瞬間に検知しやすくする。

---

# 4. 自分の苛立ちを、記録の欠落を知らせる合図として定義する

- AIに「前に言ったのに」と苛立つ瞬間を、AI性能問題ではなく自分の記録欠落の合図として定義する。
- 「それは違う」「前に話した」など、実際に言うフレーズを検知条件にする。
- 検知した時の復旧手順（どのファイルを見て何を追記するか）を同じ場所に書く。

---

# 5. 自分のやり方は「ルール」ではなく「観察」として書く

- 自分の進め方を「守るべき型」にしすぎると、合わない場面で邪魔になる。
- 各項目に「使う場面」と「使わない場面」を必ずセットで書く。
- 冒頭に「これは引き出しであってルールではない」と明記する。

共通点は、内容を変えるのではなく、判断が発生する場所を自動実行の設定・作業の分割点・ルール本文などへ移すこと。意志で自分を管理する設計は、意志が働かない日に壊れるため、置き方を変える。
